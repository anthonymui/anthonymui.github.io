Overview

DocFlow is a collaborative document editor I designed and built from scratch. The goal was to ship the strongest working version of a document editor within a defined scope.

I owned every decision: what to build, what to cut, how to structure the backend, and how to deploy a product that anyone could test immediately without any setup.

The Problem

The challenge was shipping something usable and coherent within a constrained scope, without sacrificing depth in the areas that matter most.

Scope creep risk

Open-ended prompts invite over-building. Shipping shallow coverage across every feature is worse than depth in a few.

Editing experience quality

Ensuring proper library slection to get correct formatting.

Sharing model clarity

Access control needs to be simple enough to implement quickly but coherent enough to reflect real product logic.

Deployment reliability

Deployment had to work for anyone to evaluate it.

"The hardest decisions were not technical. They were about what to cut and what to ship."

Solution & Execution

Rather than attempting every feature, I identified the highest-impact areas and built each one with care.

  • Rich text editing: Supports bold, italic, underline, headings, font sizes, lists, blockquote, and inline code with keyboard shortcut tooltips on every toolbar action.
  • Auto-save with live status indicator: Eliminated the need for a manual save action. A visible saved indicator and last-edited timestamp give users confidence without adding complexity.
  • Sharing model with three sharing levels: Owner, editor, and viewer roles are color-coded in the UI. Collaborator avatars appear in the editor header so users know who has access at a glance.
  • File import and export: Users can import .txt and .md files directly into editable documents, and export any document as PDF or Markdown. Scope was intentionally limited to formats with clear conversion paths.

Key Decisions & Tradeoffs

Every feature was evaluated against a single question: is the user impact worth the implementation cost?

  • Editor library selection: Chose an editor library that stores content in a structured format, making documents reliable to save, reopen, and rehydrate. The priority was a stable editing experience over flexibility I did not need at this scope.
  • Lightweight local database: Chose SQLite to eliminate infrastructure dependencies and keep deployment simple. The goal was a product anyone could test immediately, not a scalable backend.
  • Seeded accounts over email authentication: Mocked login kept scope reasonable while still demonstrating the full ownership and sharing model. The tradeoff was clearly documented.
  • Cut real-time collaboration: WebSockets and CRDTs would have been a significant time investment. Auto-save handles async workflows adequately at this scope.

"Scope cuts are only good decisions if you can explain them clearly. Every cut I made had a reason."

Results

Features Shipped
Full editing experience with formatting, auto-save, file import, export, sharing, search, sorting, and duplication, all working end-to-end.
Deployment
Live on Railway. Accessible in any browser with no local setup required. Seeded accounts ready to test immediately.
Permission Model
Three-tier access control with owner, editor, and viewer roles, color-coded in the UI with collaborator visibility in the editor header.
AI Workflow
Used Replit AI for code generation and Claude for product thinking. Every suggestion was evaluated against complexity vs. impact before accepting, modifying, or rejecting.

DocFlow was evaluated on product judgment and execution quality. The goal was to ship a complete, testable product with deliberate tradeoffs and clear reasoning behind every decision.

Reflection

DocFlow reinforced something I already believed: prioritization is a communication problem. The hardest part was not building, it was deciding what not to build, and being able to explain why clearly enough that someone else would agree with the call.

If I were to continue building DocFlow, the next priorities would be real-time collaboration indicators, document version history with timestamp snapshots, and a commenting layer. Each has a clear user need and a defined implementation path.
